## 常见的 I/O 模型

I/O 模型有几种：

1. 同步阻塞 I/O
2. 同步非阻塞 I/O
3. I/O 多路复用
4. 异步非阻塞 I/O，也就是 Async I/O

按照这个分类，只有第四种是异步 I/O，前面三种都是同步 I/O。

同步阻塞 I/O：在线程处理过程中，如果涉及 I/O 操作，那么当前线程会被阻塞，直到 I/O 处理完成，线程才接着处理后续流程。如果使用一个连接对应一个线程的模式，大量连接会带来线程调度和上下文切换的开销。

同步非阻塞 I/O：在线程处理过程中，如果涉及 I/O 操作，当前线程不会因为等待数据一直阻塞，而是直接返回，之后再来查询 I/O 是否已经就绪。

真实的数据处理逻辑大致是这样的：

```text
网络数据 → 网卡 → 内核 socket 接收缓冲区 → 用户缓冲区 → 程序处理
```

同步阻塞 I/O 中，如果没有数据，调用线程就会挂起。

同步非阻塞 I/O 的流程大概是：

```text
用户线程             内核

recv() ----------> 数据没有
      <----------- EAGAIN

recv() ----------> 数据没有
      <----------- EAGAIN

recv() ----------> 数据来了
                   copy
      <----------- 返回数据
```

它和同步阻塞 I/O 的区别是：没有数据时会直接返回。但是为什么说它还是同步的？

因为真正的数据读取仍然由当前线程通过 `recv()` 发起，并等待这次调用完成。

整个接收数据的逻辑可以分成两个阶段。第一阶段是等待数据，对于同步非阻塞 I/O 来说，这个阶段不再阻塞；第二阶段是把数据交给用户缓冲区，这一步仍然在 `recv()` 调用中同步完成。

同步非阻塞 I/O 最大的问题在于轮询会消耗大量 CPU。如果有很多 socket，就需要一个个检查，产生大量系统调用，其中很多只是返回 `EAGAIN`，消耗了不必要的资源。

## I/O 多路复用

这里主要讲 Linux 平台的三个 API：`select`、`poll` 和 `epoll`。

多路复用的含义是一个线程可以同时监听多个 socket。线程只阻塞一次，等待大量 fd 中的任意一个就绪。

为什么说它还是同步 I/O？因为 `epoll` 只是让线程知道某个 socket 就绪了，真正读取数据还是依赖一次 `recv()` 调用。

```text
epoll_wait()
   ↓
内核：fd3 ready
   ↓
用户线程 recv(fd3)
   ↓
内核把数据交给用户缓冲区
   ↓
recv() 返回
```

在等待数据到来的时候由 `epoll` 帮忙等待；数据就绪之后，仍然需要用户线程调用 `recv()`。

## 异步 I/O

异步 I/O 和前面的同步 I/O 有本质区别：应用发起异步读取后可以继续执行，等数据已经进入指定的用户缓冲区之后，再收到完成通知。

```text
用户线程                     内核

async_read()
   |
   |-------------------------->
   |
   | 立即返回
   ↓
继续处理其他任务              等待并完成 I/O
                              |
       <----------------------
              通知程序
```

收到通知之后，用户不需要再为同一次操作调用读取函数，直接处理缓冲区中的数据即可。
